# M5.2-R3-P0-R1 Prompt 控制诊断实验报告

## 1. 结论

P0-R1 的设计、独立身份、严格配置、确定性任务生成、污染检查、CPU 合成契约 Smoke、失败
路径和真实 Qwen3-8B GPU Pilot 均已完成。当前状态为 `COMPLETED_GATE_REJECTED`：真实实验
接受 12/40 条，Config 接受 4/20，Log Diagnosis 接受 8/20，两个任务族均未满足
14 条总接受及 10/4 语言覆盖门禁。正式 240 条扩展与 R3 训练继续阻断。

P0-R1 只检验一个假设：把原 P0 中较宽泛的“简洁推理”改为“先给结论、引用一处直接证据、
不讨论其他标签”，能否在保持原有质量约束的情况下显著降低过长推理。结果表明该 Prompt
控制只带来有限改善，不足以支持正式扩展。

## 3. 唯一允许的变量

英文 Prompt 新增以下结构约束：

1. 在一个紧凑段落中先给出所选标签；
2. 只引用输入中的一处直接证据；
3. 随后立即结束，不讨论其他标签。

中文 Prompt 使用完全对应的约束。证据内容、标签集合、答案、Verifier 和任务分布保持不变。

以下条件继续冻结：

- `Qwen/Qwen3-8B@b968826d9c46dd6066d109eabc6255188de91218`；
- 原生 GQA、BF16、Thinking 模式；
- Temperature 0.6、Top-p 0.95、Top-k 20、Repetition Penalty 1.0；
- 每个任务两个候选、最大生成 384 Token；
- Trace 不超过 192 Token、Repeated 8-gram 不超过 5%、无重复行、全局唯一；
- 完整训练序列不超过 1024 Token；
- Config/Log 各 20 条，分别为英文 14 条、中文 6 条；
- 不读取 M6 冻结评测结果。

## 5. 真实 GPU 结果

实验使用物理 GPU 7，在运行前记录约 960 MiB 已用显存、0% GPU 利用率和 34°C；项目
Preflight、模型快照、父结果哈希、配置、Git 和双 Tokenizer 环境均通过。运行绑定提交
`37563be68131b0c1c7458f170a17341e31bdfedf`。

| 任务族 | 输入 | 接受 | 英文接受 | 中文接受 | Trace Token Min/P50/P90/Max | 门禁 |
| -- | --: | --: | --: | --: | -- | -- |
| Config | 20 | 4 | 3 | 1 | 170 / 186.5 / 192 / 192 | 拒绝 |
| Log Diagnosis | 20 | 8 | 7 | 1 | 136 / 159.5 / 187 / 187 | 拒绝 |
| 合计 | 40 | 12 | 10 | 2 | — | 拒绝 |

80 次候选生成全部执行完成。选择器审计了 72 个候选，其中 12 个接受、60 个拒绝；部分任务
在第一个候选通过后不再审计第二个候选，但所有原始生成均被保留。拒绝原因只有：

| 拒绝原因 | 次数 |
| -- | --: |
| 推理超过 192 Token | 46 |
| Teacher 达到 384 Token 生成上限 | 14 |
| 两个候选均需改进 | 28 个任务 |

没有出现答案错误、JSON 无效、Think 标签错误、重复行、Repeated 8-gram、Trace 重复、
序列溢出或污染拒绝。说明当前主要问题仍是 Qwen3-8B 原生 Thinking 长度控制，而不是答案
正确性或格式解析。

### 5.1 分层结果

Config 的英文 `world_size_mismatch` 接受 2/4、`missing_checkpoint` 接受 1/3，其余英文
标签为 0；中文只有 `missing_checkpoint` 接受 1/2。Log 英文四类均有接受结果，合计 7/14；
中文只有 `collective_timeout` 接受 1/2，其余为 0。中文总接受率 2/12，仍是主要覆盖缺口。

## 7. 后续决策

P0-R1 以退出码 6 诚实收口。当前 Qwen3-8B 原生 Thinking + 单阶段 Prompt 控制组合不适合作为
R3 简洁 Trace 的正式来源，因此：

1. 不实现 240 条扩展；
2. 不启动 R3 Mixture 或双 Seed 训练；
3. 不降低 192/384 Token、14/10/4 或污染门禁；
4. 停止继续尝试同类 Prompt-only 变体；
5. 下一阶段进入 Teacher 来源策略审查，优先评估“先求解、再受约束压缩”的双阶段 Teacher
   Pipeline，并保留确定性规则 Trace 作为受控基线。

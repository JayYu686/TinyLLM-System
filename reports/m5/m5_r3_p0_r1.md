# M5.2-R3-P0-R1 Prompt 控制诊断准备报告

## 1. 结论

P0-R1 的设计、独立身份、严格配置、确定性任务生成、污染检查、CPU 合成契约 Smoke 和失败
路径已经实现。当前状态为 `READY_FOR_GPU_PILOT`，下一步只允许运行 40 条 Qwen3-8B
Teacher Pilot；本报告不包含 GPU 质量结果，也不解锁正式 240 条扩展或 R3 训练。

P0-R1 只检验一个假设：把原 P0 中较宽泛的“简洁推理”改为“先给结论、引用一处直接证据、
不讨论其他标签”，能否在保持原有质量约束的情况下显著降低过长推理。

## 3. 唯一允许的变量

英文 Prompt 新增以下结构约束：

1. 在一个紧凑段落中先给出所选标签；
2. 只引用输入中的一处直接证据；
3. 随后立即结束，不讨论其他标签。

中文 Prompt 使用完全对应的约束。证据内容、标签集合、答案、Verifier 和任务分布保持不变。

以下条件继续冻结：

- `Qwen/Qwen3-8B@b968826d9c46dd6066d109eabc6255188de91218`；
- 原生 GQA、BF16、Thinking 模式；
- Temperature 0.6、Top-p 0.95、Top-k 20、Repetition Penalty 1.0；
- 每个任务两个候选、最大生成 384 Token；
- Trace 不超过 192 Token、Repeated 8-gram 不超过 5%、无重复行、全局唯一；
- 完整训练序列不超过 1024 Token；
- Config/Log 各 20 条，分别为英文 14 条、中文 6 条；
- 不读取 M6 冻结评测结果。

## 5. 真实 GPU 门禁

真实 P0-R1 必须同时满足：

- Config 接受至少 14/20，其中英文至少 10、中文至少 4；
- Log Diagnosis 接受至少 14/20，其中英文至少 10、中文至少 4；
- 所有接受项通过答案、格式、长度、重复度、唯一性、序列长度和污染检查；
- Git Worktree 干净，模型、配置、父结果和环境身份完整。

退出码 `0` 表示通过，`6` 表示实验成功完成但质量门禁拒绝，`2/3` 分别表示契约或环境失败。
门禁拒绝时保留原始生成与聚合结果，不启动 240 条扩展。

## 6. 后续决策

- P0-R1 通过：人工内容审查后，才允许实现 240 条正式来源扩展。
- P0-R1 拒绝：记录当前 Teacher/Prompt 组合不适合作为简洁 Trace 来源，停止消耗扩展预算，
  重新审查 Teacher 来源策略。
- 任一基础设施错误：修复错误后以新输出目录重跑，不把基础设施失败计为质量结论。

## 3. 已实现链路

```text
40 个新任务
→ Dev / 历史 Pilot / P0 / P0-R1 污染检查
→ Thinking Solver
→ Solver Final JSON Exact Verify
→ Non-thinking Compressor
→ 严格 JSON Envelope
→ Compressor Final JSON Exact Verify
→ Evidence Anchor / 其他标签 / 长度 / 重复 / 唯一性检查
→ Qwen3 Thinking 训练序列渲染
→ 14/10/4 来源 Gate
```

Solver 未正确闭合或答案错误时不会调用 Compressor。Compressor 的输出独立验证，不继承
Solver 的通过状态。所有原始 Task、Solver 推理和 Compressor 输出只进入私有 Artifact；
公开结果只保留哈希、计数、长度与拒绝原因。

## 5. 真实 GPU Gate

P1 只有同时满足以下条件才通过：

| 任务族 | 总接受 | 英文 | 中文 |
| -- | --: | --: | --: |
| Config | ≥14/20 | ≥10 | ≥4 |
| Log Diagnosis | ≥14/20 | ≥10 | ≥4 |

此外要求：

- 规则控制组 40/40 结构通过但保持 `training_source_authorized=false`；
- 四路污染全部为 0；
- Git Worktree 干净；
- Solver、Compressor、Tokenizer、模型 Revision 和父证据身份完整；
- 每条接受 Trace 不超过 192 Token，训练序列不超过 1024 Token。

退出码 `0` 表示 P1 来源门禁通过，`6` 表示实验成功完成但质量门禁拒绝，`2/3` 分别表示
契约或环境失败。

## 6. 通过后的最短路径

P1 通过只会设置 `formal_source_expansion_authorized=true`。之后按以下顺序推进：

```text
人工抽样审查
→ 240 条正式来源扩展
→ 160 条 56/24 × 2 分层选择
→ R3 1M Token Mixture
→ 两个固定 Seed 训练
→ 冻结双模式评测
→ 99% Thinking 格式 + Non-thinking 回退门禁
```

P1 不通过时保留真实拒绝原因，不降低 192 Token、14/10/4、污染或 99% 门禁。
